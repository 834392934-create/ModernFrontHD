# 3.16 大规模交战与路线修复

## 使用

- 三张新地图：北海、波罗的海、波斯湾，每张 24576×16896 游戏单位、512×352 格，面积为 3.15 超大地图的 4 倍。开局选择；不改变旧存档地形。
- 玩家友军攻击：开局或局内“增益”勾选，默认关闭。指挥模式选中单位后 Ctrl＋右键点击己方目标；第一人称右键只瞄准、左键开火。手动爆炸也可能伤及己方；自动索敌不攻击友军。关闭立即保护己方并取消待执行友军攻击，已付费生产不受影响。
- R 返航：重复按键不再重置进近。空中飞机优先选择可服务的基地；落地固定翼按整机净空滑行，避开建筑和停驻载具。直升机无跑道也能维修后出发。返航仍受基地存活、电力、服务资源和合法路线限制。

## 解决的问题

1. 战斗热点：重复计算射程资料、为每个候选目标重复枚举武器、每次取枪口时遍历整个模型、远景履带链节仍更新全部骨骼。
2. 缓存只覆盖稳定资料和相同姿态的结果。目标存活、位置、检测、射程判定、弹药、碰撞与伤害仍实时计算；枪口缓存命中前仍同步当前物理姿态。
3. 超过 180 个实体时，远景履带使用共享原几何、少骨骼版本；近景或选中恢复原关节。车轮、炮塔保留动画。远景动画间隔 75 ms；超过 180 个可见实体的指挥视角阴影间隔 100 ms，第一人称恢复逐帧阴影。
4. 陆军粗栅格 A* 无路时，检查完整车体的连续直线路径，解决实际可通行但栅格被建筑膨胀遮住的走廊。仍不能穿过建筑、矿区、水域或完全封闭的障碍。预算不足只等待，不错误重写现有路线。
5. 飞机滑行目标按坐标比较，避免每帧重置；规划检查整机与停驻单位，限定重算频率。角度和位置一起通过碰撞检查后才更新，防止机翼原地转入障碍。
6. 密集队形规划预先计算当前规划内的分层和间距；避碰候选先比较理论最高分，只有可能胜过当前候选才继续精确检查。传感器只记住优先检查的观察者，每次仍重新验证检测、存活、位置、电力与 EMP。实体索引检查当前数组和对象，替换、死亡与存档加载不会返回旧对象。
7. FPS 计数使用真实时间，修正长帧被时间上限截断后计数偏高的问题。

## 复现与证据

```powershell
node --test tests/*.test.cjs
.\build-desktop.ps1 -OutputDirectory release/ModernFrontHD-3.16.0
node tests/recovery-maps-friendly-desktop.cjs
node tests/peak-combat-desktop.cjs
$env:PEAK_UNITS='640'
$env:PEAK_MS='60000'
$env:PEAK_PROFILE='0'
$env:PEAK_LABEL='640'
node tests/peak-combat-desktop.cjs
```

GPU 测试逐个执行，不与完整 CPU 套件并行。测试启动实际 EXE，使用独立 profile，并检查包内源码哈希、授权模型加载状态、材质与来源。默认压力样本为 320 个作战单位＋2 总部、沙漠地图、最高 AI、公开射程、无视野增益、12 秒采样；36 u 横向间隔刻意制造密集拥挤。它是可复现压力场景，不是用户原存档。完整性能数值见 [最终报告](v3.16.0-validation.json)、[320 单位样本](peak-final-desktop-report.json)、[640 单位样本](peak-640-desktop-report.json) 和 [3.15 基线](performance/peak-v3.15-baseline.json)。

FPS、P95 帧时间、模拟时间/实际时间、实体数、同时在飞弹体、分辨率与 GPU 都单独记录。函数计时存在嵌套，不能相加；draw 计时是 CPU 耗时，不是 GPU 时间。640 场景不用 CPU sampling，因此仅作更高负载边界，不能当作与基线严格配对的提升倍数。60 秒也不是长期稳定性证明。

海岸来自已固定版本的 Natural Earth 1:50,000,000 数据，地图为压缩地理参考，基地、矿山和部署均为虚构。不是 50 米精度，也不宣称完整真实装备性能。
