# 航空舰联队与集成约定

`src/carrier-operations.js` 将航母攻击转成真实飞机实体出动，不生成航母本体的远程伤害弹。所有数值均为游戏尺度；现有原创职责模型复用不表示对应国家已部署该舰机组合。

- 常规航空舰拥有3个付费联队槽：反舰攻击机、近距支援机、远程截击机。优先补充当前目标对应槽，随后补齐混合联队。
- 韩国当前外形为独岛级航空舰，仅使用2个原创护航直升机槽，保留该职责现有仅对空目标域，不增加未经实现的固定翼或反舰能力。
- 首次准备2秒；每架按原角色cost付费；损失后等待原角色生产time（至少8秒）再付费补充。无限资源模式仍走统一spend逻辑。联队不会超出容量，实体总量达到950时暂停补充。
- 甲板一次容纳1架起降/维修飞机。准备、加速、爬升、巡航/通场、移动甲板进近、减速、滑行、5秒以上维修、再出动均走真实实体。原机场起降流程保留。
- 停机飞机每帧按舰体位置/角度更新；没有冻结世界落点。维修后重新起飞待命，其他返航机在空中等待，避免多个完整模型在甲板叠放。
- 航母沉没时甲板上飞机损失，已经离舰飞机继续作战并可改降兼容航空舰/机场；空中残存飞机继续参与全灭胜负统计。
- 手动驾驶飞机时联队调度不覆盖其命令；鼠标解锁时保持原飞行暂停保护，但在甲板上的飞机仍跟随舰体。

集成入口：

1. Browser在`aircraft-flight.js`之后、`sim.js`之前加载模块；Node在sim初始化时require模块。
2. `emitShot`航母分支先调用`WarCarrierOperations.requestStrike(game, carrier, target || aim)`，返回值表示是否受理任务，不生成第二份直接伤害。
3. 每个模拟步、尸体清理前，对所有carrier实体（含当帧死亡）调用`updateCarrier(game, carrier, dt)`。死亡入口负责处理甲板上仍被手动驾驶的飞机。
4. 存档逐实体执行`validate(entity)`；恢复实体与teams之后执行`validateGame(game)`检查容量、飞机归属和甲板引用。
5. `status(game, carrier)`提供`capacity/active/airborne/onDeck/repairing/planeIds/description/mission/waitingForFunds/replacementCost`用于HUD。主武器应显示舰载机数量/出动状态，避免把派遣描述成普通舰炮。

`requestStrike`验证目标域、敌我、目标存在、坐标范围和舰载航空任务范围。实际飞机仍经过自身射程/视野/朝向/目标域结算。区域指令选择现有对陆支援机；不会给予任意跨域伤害。

验证命令：`node --test tests/carrier-operations.test.cjs tests/aircraft-flight.test.cjs`。测试覆盖真实模拟伤害、成本与延迟补机、完整混合联队改换目标、移动转向舰体回收、同时返航互斥、韩国垂直返航、FPS接管/失焦、航母沉没与全灭规则、存档归属校验、着舰中止后存档，以及原机场全部航空角色回归。
