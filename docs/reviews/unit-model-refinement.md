# 全作战单元表面细化批次（2026-10-24）

本批由独立建模 agent 执行。目标是让现有部件的材质区别更可信，并给全量模型建立不破坏机构、炮口与导入资产的验证。**这是现有外观的材质修整，不代表 462 个槽位已按实物照片完成重建或通过完整视觉验收。**

## 覆盖盘点

| 游戏角色类别 | kind 数 | 六阵营槽位数 |
| --- | ---: | ---: |
| 单兵 | 8 | 48 |
| 地面车辆 | 14 | 84 |
| 水面舰艇 | 15 | 90 |
| 水下单元 | 4 | 24 |
| 飞行器（含明确架空的全域角色） | 18 | 108 |
| 太空单元 | 18 | 108 |
| 合计 | 77 | 462 |

统计按现有 `WarData.U` 的人物、space、air、underwater、naval 顺序分类，只作界面/模型范围归类。具体来源及未验收状态仍以 `model-inventory.json` 和 `ACCEPTANCE_POLICY.md` 为准。

458 个原创程序槽位使用新的表面修整；4 个授权槽位（俄 T-90M、美 Burke、美/韩 AH-64）保留完整原材质。AH-64 导入文件本身使用材质参数，没有位图纹理，不将其误报为“贴图丢失”。

## 实际变更

- 从原有 surface 标签和项目明确的材质颜色常量识别涂漆、光学窗、钢、橡胶、布料、太阳能板、隔热箔。老模型中轮胎橡胶与涂漆装甲共用反光参数的问题在材质层分开；明确布料标签优先，保留人员原有阵营装具及迷彩。
- 原有高频颗粒按屏幕像素覆盖率衰减；近景保留轻微表面变化，远景收敛到平均色。该修改针对 shader 中的颗粒项，不冒称已量测整场游戏的运动闪烁或帧率提升。
- 每个原材质缓存一个变体、每个几何对象仅新增一字节/顶点的类别属性；未添加三角面或额外绘制网格。保留原顶点、法线、色彩、蒙皮、发射口名称、机构父子关系、变换及碰撞包络。
- 导入 GLB、带贴图的材质、透明材质及发光材质整项保留，不进行统一换色。不改变 `preserveMaterial` 资产的署名、许可证和加载失败检测。
- 六代机、未知改型、帝国和其他概念角色仅接受既有材质修整；没有进一步生成或宣称真实外形。

材质数值是游戏美术参数，未将其表述为实测装备的金属度或粗糙度。

## 集成接口

`src/model-unit-refinement.js` 暴露 `WarUnitRefinement.apply(model, kind, faction)`。在 `WarModels.create` 的运动机构提取之后、模板缓存之前调用。主战场、模型检视器、缩略图通过同一工厂得到结果；模块不自行替换工厂或注册新型号。

检视器迷彩按钮同时同步 `WarModels.material.userData.camo`、现有检视材质及 `WarDetail.material`，避免原程序模型材质保留后丢失按钮作用。

## 验证

1. `node --test tests/unit-model-refinement.test.cjs`：6 项测试；逐一构建全部 462 程序槽位，检查顶点、法线、颜色、蒙皮、索引、三角数量、节点、矩阵和包络不变；检查橡胶/钢/玻璃分类，保护透明/发光/贴图材质；已修整网格换父节点仍不重复安装 shader。
2. `node tests/unit-model-refinement-browser.cjs`：实际加载 3 个授权资产、对应 4 槽位；核验源链接、材质身份及原有纹理保留；全 462 槽位有限包络；五类别各两型号的同光照前后截图；实际迷彩控件仍改变渲染结果。`--preview` 仅供尚未挂入入口时隔离研究，其 `integrated:false` 报告不能充当交付验收。
3. 截图：`screenshots/unit-model-refinement-ground.png`、`naval.png`、`air.png`、`space.png`、`personnel.png`（均带 `unit-model-refinement-` 前缀）。左为旧表面、右为修整表面；差异克制，主要在光泽和细粒稳定性。
4. 正式发布仍需主代理验证实际启动器选中的 EXE、源文件 hash、离线导入资产 ready、更新缩略图及整体交互。离屏截图不能代替这些检查。

## 仍未完成的实物验收

- 49 个已有实物参考槽位仍需按各自具体构型补齐多角度、比例和细节复核；不因本批测试通过而自动修改原验收状态。
- 地面车辆的舱盖/格栅/轮组细节，航空器具体批次表面和内部不可见部位，舰艇舰桥/舰岛细节、水下未公开部位仍保留原边界。
- 通用游戏角色没有足够来源匹配某一制式型号；本批未为其补造现实身份。
- 自发光、授权贴图、已设置透明的原材质是有意保留，不代表它们已经完成新的逐型外观优化。

技术依据：Three.js 官方 [Material](https://threejs.org/docs/pages/Material.html)（材质回调和程序缓存）及 [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)（粗糙度/金属度工作流）。本批无新增实物构型，因此没有以未核验的搜索摘要替代照片证据，也没有下载研究照片随包分发。
