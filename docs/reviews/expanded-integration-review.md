# 四域兵种与防御范围集成独立审查

审查日期：2026-10-16。范围：未提交的 `src/sim.js`、`src/roster.js`、`src/ranges.js`、`src/app.js`，以及实际调用链 `src/battle3d.js`。本报告不代表模型实物还原验收。

## 第一轮确认缺陷

### P1：范围渲染调用误入场景初始化，页面无法启动

- 初次定位：`src/battle3d.js:103`。
- `prepare(game)` 矿山创建循环前调用 `collect(game, ui, this)` 和 `draw(g, ...)`，但此作用域没有 `ui`、`g`。
- 实际 headless Chromium 打开 `http://127.0.0.1:8765/`，捕获 `ReferenceError: ui is not defined at Battle3D.prepare (.../src/battle3d.js:103:55)`，`window.ModernFront` 不存在。
- 修复建议：移至 `draw(game, ui, ...)` 的屏幕叠加层矿山文字绘制前，确保 `g` 为对应画布上下文。

### P1：生产筛选和范围控件初始化误入阵营按钮回调

- 初次定位：`src/app.js:133–140`，默认开局读取约 `321`，快捷键约 `765`。
- 控件只有点击阵营时才创建；默认直接开始会访问不存在的 `#unit-filters`/`#range-readout`。多次换阵营会重复插入相同 id。`toggleRanges` 定义在阵营 onclick 局部作用域，外层 V 快捷键无法访问。
- 这是源码作用域确认的问题；第一项启动错误挡住了继续操作，不能宣称当时已通过浏览器逐条复现本项。
- 修复建议：将整块初始化移至脚本底部的一次性初始化，放在最终 `setupMenu()` 调用之前。回归默认直接开始、连续换阵营、V 循环、控件 id 唯一。

### P2：AI 海军指令不匹配新兵种目标域及支援职责

- 定位：`src/sim.js:826–829`，独立海军分支选择任意敌舰并下达追击命令，不校验目标域和视野；无敌舰时不推进。
- 新维修舰、仅对空的防空舰、仅对陆军/建筑的岸攻舰都会收到追敌舰指令，即使自身无法攻击该目标；无敌舰时岸攻舰无法参与登陆岸火力支援。
- 本报告第一稿将其错误概括为“完全没有海军命令”；经主 agent 指出并重新读取，已明确撤回该结论。
- 建议选择可攻击且已发现的目标，无接敌目标时向可达水域前进；维修舰跟随同域受损友军，不能冲锋追敌。海军目的地必须基于 `navalBlocked`/海军路径。

### P2：海岸目标候选缺少水域连通性筛选

- 定位：`src/sim.js:763–770`，`navalApproach` 遍历全部水格，未限定与船舶处于同一连通水域。
- 可复现：river 地图，岸攻舰在 `(2352,1992)`，目标坦克在 `(1300,900)`，函数选出 `(1512,840)`；该格确为水，但桥梁切断河段，`findPath({blocked: map.navalBlocked}, 2352,1992,1512,840)` 返回空路径。
- 结果：舰船接受不可达的河段目的地，无法按预期接敌。仅验证目的地“是水格”不足以通过导航验收。
- 建议：使用静态海军地图的连通分量（可缓存）筛选与舰船连通的候选水格，再做距离评分；增加该内河隔断复现作为回归。

### 第三轮复核：该 P2 已关闭

- 已检查修复实现：`navalApproach` 对静态海军地图执行四邻接洪泛，缓存水域连通分量，仅在舰船所属水域内选择候选点。
- 独立重跑原复现：从 `(2352,1992)` 接近 `(1300,900)`，现在选择 `(1464,312)`；`findPath` 返回 **80 个路径点**，目标格及全部路径点均为可航行水格。原先不可达河段不再被选中。
