## 原生回归发现：暂停后重新锁定鼠标（2026-10-19）

此前“没有剩余已复现的 CPU 阻断”仅描述当时 CPU 证据，**不等于实际 EXE 通过**。主 agent 在真实独立版旧 first-person 回归中发现：暂停且鼠标未锁定时，画布点击在请求 pointer lock 之前即被 scopeAvailable 的暂停条件挡住，不能按交互合同恢复鼠标锁定。

实现方为该路径新增了先失败后通过的 CPU 回归，并调整 pointerdown 守卫顺序：

1. 先排除非驾驶状态、菜单/军械库、主模态、隐藏/失焦页面和按钮目标。
2. 对允许的画布点击阻止默认和事件继续传播；未锁定时只请求 pointer lock 并返回。
3. 已锁定后，再由 scopeAvailable 拦截暂停状态；暂停时不设置 fire/ads，不启用光学瞄准，不提交射击。lock() 也仅在未暂停时设置 flightReady。

独立只读复核上述顺序，并实际运行 `node --test --test-name-pattern="paused unlocked canvas" tests/unified-aim.test.cjs`：**1 / 1 通过**。该用例覆盖左右鼠标键；暂停未锁定时请求一次锁定，飞行/开火/右键瞄准保持关闭；暂停已锁定时点击仍不启用武器；非驾驶、隐藏、失焦、主模态、换乘菜单和军械库状态不会申请锁定。

主 agent / 实现方通知相关 CPU **74 项通过**，已重新构建并启动原生 first-person 全 **77 单位**与全量 CPU 重跑；完整 CPU 用例总数新增到 **454**。本监督此时没有读取最终重跑结果，故不把 454 项或原生回归写成已通过，最终结果由主 agent 补充。此轮未改运行时、未跑 GPU，仅更新本报告。
