# 3.16 本机性能与行为回归

- `local-skill-agent-router`：查阅 Hub 清单，沿用本机原生能力，不引入新的运行依赖。
- `explore`：两名只读代理梳理返航/地面导航、友军攻击/地图；主代理核对路径，记录 `.tmp/explore/peak-return-navigation-316.md`，统一实施。
- `diagnose`：先在实际 Electron 中复现 320 个作战单位交战掉帧，采集 CPU sampling 和嵌套函数计时，再修改热点。地图、分辨率、单位配比与采样方法保持一致；嵌套时间不能相加，draw 是 CPU 时间，不冒称 GPU 时间。

复核发现并修复：直升机无跑道维修后不出发；返航重复重置进近；滑行路径不断重置；停驻单位绕行；粗栅格掩盖合法建筑走廊；友军攻击远处/排队目标不恢复；缓存枪口跳过第一人称物理姿态同步。原测试中的密集队形退化促使直线路径限定为 A* 无路时的合法后备，保持原有拥堵调度。

优化边界：稳定的射程资料可复用；位置、存活、遮挡、命中、弹药和电力保持实时判断。远景只减少独立履带链节骨骼，保留原几何、材质和车轮/炮塔；近景和选中单位恢复完整关节。压测使用隔离 profile，不终止用户旧对局。不声称 DLSS、H3 推理或真实装备性能认证。

640 单位加压暴露了另一档负载边界。继续按 sampling 证据改善实体索引、空间查询、重复编队净空检查、武器选择临时数组和避碰候选剪枝；传感器仅复用观察者线索，实时重验所有条件。只读代理对武器选择 1728 组、缺弹切换 540 组进行旧新对照，结果相同。新增测试覆盖相同帧内对象替换、断电、EMP、位置变化和空间查询顺序。实际是否达到流畅预算单独记录，不用“测试通过”代替 FPS。

最终独立版、CPU 回归与压力测试的实际数据见 `docs/v3.16.0-validation.json`。
