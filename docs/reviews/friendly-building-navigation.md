# 己方建筑绕行验证（2026-10-20）

范围为模拟与 CPU 验证，不代替独立版画面验收。未运行 GPU/Electron，未关闭玩家进程，未提交 Git。

## 可复现根因与修复

原 `.tmp/friendly-building-baseline.cjs` 在无地形干扰的地图上放置 16 栋建筑形成长墙，命令从 `(1000,1400)` 到 `(2200,1400)`。120 秒后坦克、驱逐舰、浅潜艇与低空直升机均未到达；命令之后在终点新建建筑，同四种单位仍有订单，累计重规划 39–48 次。

三个路径环节的建筑约束不一致：原静态网格只加入部分地面建筑且未按移动体尺寸扩张；普通路线的快捷段不检查建筑；局部可视图最多看附近 16 个障碍，会穿过远处未纳入的建筑墙。另旧命令终点不因施工更新，矿车使用固定矿口。

修复采用现有导航包络与垂直重叠规则：共享各领域的建筑网格、所有快捷段检查建筑、局部绕行边再检查完整建筑集合。后建建筑占据无实体目标的移动落点时，改用附近合法落点；Shift 队列与攻击目标保留。矿车在矿山周边 160 单位范围内选择合法入口，生产出生检查增加矿堆避让。建筑不再被路径忽略，实际移动碰撞没有关闭。

地形仍按真实模型旋转 OBB 检查，没有用外接圆扩大地形障碍，避免封死原本可以通过的窄路。高空、轨道和足够深的水下层不受无垂直重叠建筑阻挡。建筑的高度包络沿用已有模拟值，未增加真实海底基础模型。

## CPU 样本与缓存边界

Windows，Intel i5-12400F，Node v24.14.0；无渲染；固定 `dt=0.05s`，1200 步、60 秒模拟，26 栋建筑，混编六类地面车辆从地图左侧绕墙到右侧。脚本 `.tmp/building-cpu-benchmark.cjs`。单次样本包含 JIT/调度抖动，不能换算为实际游戏 FPS。

|车辆数|step 均值|p95|最大|到位数（60秒）|网格请求/构建|
|---|---:|---:|---:|---:|---:|
|48|2.66 ms|7.10 ms|18.07 ms|13/48|95/75|
|96|5.43 ms|15.76 ms|41.69 ms|23/96|350/310|

网格仅在预算内的 A* 请求时生成，不逐实体逐帧重建；同 tick、相同领域/半径/实际相交建筑集合共享结果。下一个 tick 换缓存，且同 tick 新建/拆除、位置或半径变化会改变缓存键。地图地形在同一模拟 tick 内按现有静态地图契约使用，外部调试代码直接修改地形数组应先推进 tick。

上述压力样本并不证明 60 秒内全部到达；密集移动体、封闭基地和完全围住矿山仍有真实可达性限制。绘制效果与真实鼠标操作由主线程独立版串行验收。

## 独立审查后的高空快速路径修正

审查员发现初版在每架空中单位每帧执行全长 `segment`，5000 单位远目标触发大半径空间查询，访问大量空桶；100 架、每架 10 次，共 1000 次调用的初版样本耗时 258–269 ms。这是新引入的 CPU 回归，已修复。

`buildingSegmentClear` 现在直接检查建筑线段圆相交及高度层。普通空军直达只调用该检查；完整 `crowd.segment` 的空中地形检查仅一次终点边界检测，只有绕移动体的路线才额外进行动态空间查询。低空建筑阻挡、实际逐步碰撞和地面地形采样保留。

同一审查探针修后 1000 次耗时 3.22 / 0.688 / 0.619 ms（3 轮，第一轮含 JIT），全部 1000 次结果一致。合同测试断言 1000 次普通空中路线不调用空间查询、只有 1000 次终点地形检查，降至建筑高度后仍正确阻挡。该微基准只测这一函数路径，不代表游戏整体帧率提升。
