# 第一人称输入与镜头审查 · 2026-10-18

范围：`src/direct-control.js`；关联只读检查模拟器、主循环、三维渲染和第一人称前景模型。没有更改飞机的速度、惯性、转弯速率或滚转物理。

## 证据与修复

1. **闲置画面仍有轻微移动**：原默认 `motion=true`，前景模型 `fps-viewmodel.js` 的 `sway=sin(time*1.7)*.002` 与移动按键无关。默认关闭人为晃动，M 仍可主动开启。该机制是代码可确定的闲置移动来源；不能将其当成用户机器全部漂移症状的唯一根因。
2. **锁定/恢复时视角突跳**：原鼠标入口直接累计所有 movementX/Y，既不排除非有限值，也不识别坐标重置造成的大增量。合成事件回归证明旧实现会把 yaw 变成 NaN、接收 2000 px 位移或首个锁定事件。现在每次 pointer-lock 切换清输入，丢弃接下来的首个相对事件，并过滤非有限与单事件超过 `max(300, min(width,height)/2)` 的任一轴增量。不声称合成事件证明了真实驱动一定发送异常事件。
3. **恢复后继续朝旧方向转**：失焦或解锁只清按键而保留期望飞机姿态，重新启动 flightEnabled 后继续追旧 yaw/pitch。现在清输入同时把飞机期望姿态同步为当前机体姿态，保留当前速度与正常操纵时的气动转弯/滚转。
4. **暂停期间按键可残留**：旧代码即使暂停也会把 W 等加入 keys；恢复后可以产生未新按的运动。现仅在锁定、可运行且可见时接收运动按键；换乘菜单打开时 submit 强制零运动/火控。窗口隐藏和 blur 均清输入。
5. **人员跳跃输入与相机**：人员判定沿用 `(modelKind || kind) === 'infantry'`，覆盖医疗与狙击人员。Space 提交 jump 布尔，由模拟层实现按下沿与落地；P 暂停。非人员保留 Space 暂停兼容。相机读取模拟层已经包含 jumpHeight 的 entityAltitude，增加一次眼高9.5u，没有再次叠加跳跃。
6. **飞机鼠标方向**：`air && !space` 的 X、Y 两轴反向；地面、水下和太空为普通观察方向，避免先前 `air` 把轨道观察也反向。直升机与固定翼帮助文字同步。
7. **RTS 输入边界**：进入第一人称后调用 onEnter 回调，交由应用层清战略输入；模态框激活时不拦截 Escape 等键，同时阻断驾驶键鼠/提交；应用已有 onExit 清 keys，不把它误报为已确认的退出 bug。

## 验证

- 新建 `tests/input-stability.test.cjs`，用实际 Three.js 相机和隔离 DOM 事件入口，初始9项在修复前均失败；修复后新增模态输入隔离检查，随后真实GPU复测发现短按边沿丢失，补入事件即时提交后最终11/11通过。
- `node --test tests/input-stability.test.cjs tests/direct-control.test.cjs tests/depth-flight.test.cjs`：初轮45/45通过；短按修复后单独输入11/11通过。
- `node --check src/direct-control.js`：通过。
- 没有并行启动 GPU；真实浏览器与打包 EXE 的相对鼠标、人员跳跃、菜单和静止画面检查由主线程串行执行，结果以主线程报告为准。

## 边界

- 正常飞机飞行中的前进惯性、姿态渐变和转弯滚转保留，不能与无输入镜头漂移混为一谈。
- 为过滤锁定坐标重置，第一次鼠标事件被丢弃；极端快速甩动若单事件超过阈值也被忽略，不放大成巨大转向。
- M 开启后仍有设计上的呼吸/步行前景晃动，默认关闭；开火、受击及战场实体动画仍然保留。
- 没有宣称全游戏不存在其他 bug；本报告覆盖上述输入、相机与模拟边界。

## GPU反馈后修复：快速第二跳

主线程真实界面发现：释放与再次按下 Space 在一个固定步进周期内完成时，旧的逐帧状态采样可能未观察到 release，第二跳丢失。控制器现于人员 Space keydown 和 keyup 当场 submit，模拟层以独立 jumpPending 保存地面按下沿，逐帧重复提交不生成新边沿。clearInput 发送 cancelJump:true，暂停、失焦、解锁及菜单清输入会取消尚未消费的跳跃。输入测试直接依次派发 down/up/down，在没有任何 render 或 physics tick 时确认模拟入口收到 true/false/true，且同步持有的 W 不受影响。模拟层负责空中按下不预约落地跳及长按不连跳。
